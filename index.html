Modubotics is exploring modular robotics. We want to make it easier to assemble, change and repair robotic systems without redesigning the whole machine each time a requirement changes.

Building a robot involves more than choosing motors and writing control software. Mechanical connections, power, sensing and communication all have to work together. A change in one part can mean reworking several others. Much of that effort goes into integration before the robot can do anything useful.

Our interest is in the interfaces between these parts. We want to understand what can be shared across different machines, what needs to remain specific to a task, and where modularity actually reduces the work involved. That means considering how components attach, how they exchange power and data, and how the software describes and controls an assembled system.

Modularity has costs. Connectors take space. Shared interfaces can limit performance. A component designed for several uses may be less efficient than one made for a single job. We want to be explicit about those tradeoffs and judge an approach by whether it makes a working system easier to build and maintain.

Repair and reuse matter to us for the same reason. Replacing a failed part should not require discarding everything around it. Changing a sensor or actuator should not automatically require rewriting the rest of the software. We want to work towards systems whose parts can be understood, tested and replaced independently.

This is an early effort. The starting point is to investigate these questions through building and testing, then let the results determine what is worth developing further. If you work on robotics or have a problem where a modular system could be useful, write to hello@modubotics.in.
